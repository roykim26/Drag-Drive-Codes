## 0. 本轮已实施（代码 + 已部署）

改动文件：`04-site/build.py`（`_headers` 生成段）。

| 头 | 值 | 作用 | 影响面 |
|---|---|---|---|
| `Strict-Transport-Security` | `max-age=86400` | 强制后续访问走 HTTPS，挡 SSL-strip / 降级 | 浏览器缓存 1 天；不含 `includeSubDomains`、不含 `preload` |
| `Content-Security-Policy-Report-Only` | 见 `dist/_headers` | 只上报、不拦截；把「将来要强制的 CSP」先落地成可审查的文本 | **零拦截**，不影响复制按钮、GA、Cloudflare 统计 |
| `Permissions-Policy` | 追加 `payment=(), usb=()` | 关掉站点用不到的浏览器能力 | 无 |

CSP 里显式放行了实际会用到的来源：`'self'`、内联 `script/style`（站点用内联，暂不能去掉 `'unsafe-inline'`）、`googletagmanager.com`（GA4，仅同意后加载）、`pagead2.googlesyndication.com` / `doubleclick.net`（AdSense，当前关闭）、`static.cloudflareinsights.com`（Cloudflare 边缘注入的统计脚本）、`twelve.tools`（页脚徽章图片）。

**验证（线上实测，2026-11-21）**

```
$ curl -sSI https://dragdrivecodes.space/?cb=sec1
HTTP/1.1 200 OK
strict-transport-security: max-age=86400
content-security-policy-report-only: default-src 'self'; ... upgrade-insecure-requests
permissions-policy: geolocation=(), microphone=(), camera=(), payment=(), usb=(), interest-cohort=()
referrer-policy: strict-origin-when-cross-origin
x-content-type-options: nosniff
x-frame-options: DENY
```

`/codes/ddsthx200kroadto225klikes/` 与 404 页同样带 HSTS。构建结果未变：23 条 sitemap、24 个 HTML、广告字节 0。

**回滚（任一项都可独立回滚）**

1. 删掉 `build.py` 里对应的 `Strict-Transport-Security` 或 `Content-Security-Policy-Report-Only` 行；
2. `python build.py`；
3. `npx wrangler pages deploy dist --project-name drag-drive-codes`。

HSTS 回滚后，已访问过的浏览器仍会在 ≤24 小时内强制 HTTPS（这正是把它设为 1 天而不是 1 年的原因）。CSP-Report-Only 删除后立即无任何影响。

## 3. ECS 加固（需确认后执行，含回滚）

> 前提：这台机器同时承载其他项目，且当前自动化靠密码 SSH。**任何一步都不要一次全做**，按顺序、每步验证。

### 3.1 推荐顺序

1. **阿里云安全组收窄 22 端口来源**（控制台：ECS → 安全组 → 入方向）。只放行你家/公司出口 IP；至少不要把 22 暴露给 `0.0.0.0/0`。
   - 回滚：安全组规则改回原值，秒级生效，不会锁死已有连接之外的访问。
   - 注意：先确认自己当前出口 IP 再加规则，避免把自己锁在外面。
2. **加 SSH 公钥并验证**：`ssh-copy-id` 后新开一个会话确认能登，再动 sshd 配置。
3. **fail2ban（已完成 2026-11-21）**：从 EPEL 安装 `fail2ban-1.0.2`，仅启用 `sshd` jail：
   ```ini
   [sshd]
   enabled = true
   maxretry = 5
   findtime = 10m
   bantime = 1h
   ignoreip = 127.0.0.1/8 ::1
   ```
   `banaction = iptables-multiport`（写入 `/etc/fail2ban/jail.d/00-banaction.local`）。`fail2ban-client -t` 通过，服务 `active / enabled`；启动后立即识别 378 次失败并封禁 2 个 IP，`iptables -S` 可见 `f2b-sshd` 链。
   - 回滚：`systemctl disable --now fail2ban`（已封 IP 随服务停止解除），或 `fail2ban-client unban --all`。
4. **改 sshd**（先 `sshd -t` 校验，保留一个已登录会话再 reload）：
   ```
   PermitRootLogin prohibit-password
   PasswordAuthentication no        # 确认所有人和自动化都改用密钥后再做
   X11Forwarding no
   AllowTcpForwarding no            # 若其他项目需要端口转发则保留 yes
   ```
   - 回滚：改回原值 + `systemctl reload sshd`；阿里云控制台 VNC 可作为兜底入口。
5. **rpcbind**：先 `mount | grep nfs`、`exportfs -v` 确认没人用，再 `systemctl disable --now rpcbind.socket rpcbind`。
6. **admin 目录权限**：`chmod 700 /home/admin/.ssh`。

### 3.2 巡检脚本自身

- `patrol.py` / wrapper：755 root:root，普通用户不可写 → 不能被替换执行。
- `patrol.env` / `codes.json`：640 root:ddc，只有 root 与 ddc 组可读。
- webhook 只存在于 env，脚本与 journal 都不打印 URL（实测 14 天 0 次）。
- 建议：给这个飞书机器人单独命名（如 `DDC 巡检`），一旦怀疑泄漏，直接在飞书后台重置 webhook，不影响其他机器人。

## 4. Cloudflare 后台操作（需要你点击）

> 控制台路径以 Free 计划为准；不同账号灰度可能略有差异。**每项都给了回滚动作。**

| # | 位置 | 操作 | 回滚 | 影响面 |
|---|---|---|---|---|
| 1 | SSL/TLS → Overview | 确认加密模式为 **Full (strict)** | 改回 Full/Flexible | 若源站证书无效会 526；Pages 自定义域不受影响 |
| 2 | SSL/TLS → Edge Certificates | **Always Use HTTPS: On**（当前行为已 301，确认开关即可） | Off | 无 |
| 3 | SSL/TLS → Edge Certificates | **Minimum TLS Version: TLS 1.2** | 改回 1.0/1.1 | 极老客户端会被拒；现代浏览器无感 |
| 4 | SSL/TLS → Edge Certificates | **HSTS：保持 Off** | — | 本轮已由站点 `_headers` 下发 1 天 HSTS；两处同时开会重复/冲突。二选一，建议先用代码里的短周期版本 |
| 5 | Security → WAF → Managed rules | 部署 **Cloudflare Managed Ruleset**（若 Free 计划提供；没有则跳过） | 规则组 Disable / 删除 | 可能误伤极少数请求；先看 Security Events 再调 |
| 6 | Security → Bots | **Bot Fight Mode: On** | Off | 会挑战部分自动化流量；Googlebot 等已验证机器人不受影响；对假流量/刷点击有效 |
| 7 | Security → WAF → Rate limiting rules | 新建两条（见下） | 规则 Disable | 只影响超阈值 IP，正常用户无感 |
| 8 | Security → Settings | Security Level **Medium**；Browser Integrity Check **On** | 改回 Essentially Off / Off | Medium 可能挑战可疑 UA |

| # | 结果 |
|---|---|
| 1 加密模式 | 未改（本轮只动 TLS 最低版本） |
| 2 Always Use HTTPS | 已生效（HTTP 301），未再切换 |
| 3 Minimum TLS 1.2 | **已完成**（原 TLS 1.0） |
| 4 HSTS | **确认 Off**，未开启 |
| 5 Managed Ruleset | **不可用**：原文 "Managed rules are available starting on the Pro plan." |
| 6 Bot Fight Mode | **已开启**，刷新后 `toggle_state=on` |
| 7 Rate limiting | **未创建**：Free 仅 10 seconds + Block，按约束跳过；配额仍为 0/1 |
| 8 Security Level / BIC | Security Level 已改为自动模式不可选；Browser Integrity Check **已开启** |

> Free 计划下若要限速，唯一组合是「10 秒窗口 + Block」，对正常读者误伤概率高，不建议为凑配置而上。真遇到攻击，临时打开 "I'm under attack mode" 更可控；长期方案是升级 Pro 后按原计划上 1 分钟 + Managed Challenge。

速率限制建议（升级 Pro 后执行，先「Managed Challenge」，不要直接 Block）：

- 规则 A：`http.request.uri.path matches "^/codes/"`，同一 IP **60 次/分钟** → Managed Challenge。
- 规则 B：全站同一 IP **120 次/分钟** → Managed Challenge。
- 若 Free 计划只允许 1 条，优先保留规则 A（码页是最可能被脚本刷的入口）。
- 阈值依据：正常用户一分钟内不会打开 60 个码页；搜索引擎抓取频率远低于此，且 CF 的 verified bot 可排除。

> 恶意点击（点击欺诈）主要发生在**广告点击**层面，边缘只能降低「机器人反复加载页面/触发广告位」的概率；真正的无效点击识别由 Google 侧完成，见 §6。

## 5. CSP 从 Report-Only 切到强制

1. 保持当前 Report-Only 至少 7 天；
2. 用 Chrome DevTools 打开首页、任一码页、`/privacy/`、`/contact/`，看 Console 是否有 `[Report Only] Refused to ...`；
3. 若只有已知的 `'unsafe-inline'` 提示、无实际资源被拒，把 `build.py` 里的头名改成 `Content-Security-Policy`，重建部署；
4. 回滚：把头名改回 `Content-Security-Policy-Report-Only` 并重新部署（1 分钟内生效）。

不要在没有观察的情况下直接强制：内联脚本一旦被拦，复制按钮和 consent 条会静默失效。

## 6. AdSense 无效流量：观测与防护准备（广告当前关闭）

现状：`ads.enabled=false`，页面 0 字节广告；GA4 仅在接受后加载；Cloudflare Web Analytics 在边缘统计。接 AdSense 前建议按下面顺序做：

1. **先开边缘防护再开广告**：§4 的 Bot Fight Mode + 速率限制先跑一周，确认 Security Events 里没有误伤正常来源。
2. **观测手段（不新增跟踪脚本、不破坏隐私承诺）**：
   - Cloudflare 后台 Analytics → Security / Traffic：按国家、ASN、UA、referer 看异常集中度；
   - Cloudflare Web Analytics：看单页 PV 突增、跳出率异常、来源域名突变；
   - GA4（仅同意用户）：看 `copy_code` 事件与 session 的比值，异常高说明脚本在刷交互；
   - AdSense 后台「政策中心 → 无效流量」：上线后每周看一次，出现「无效流量」提示先查来源再决定是否屏蔽。
3. **不建议做的事**：不引第三方反欺诈像素（会破坏「唯一第三方脚本」的隐私表述）、不记录 IP 到自建日志（Pages 无源站日志，Logpush 是付费项）。
4. **可落地的阈值**（人工巡检用）：同一国家/ASN 占当日 PV >60% 且转化事件为 0；单页 PV 环比 >5 倍；`copy_code`/PV >0.8。命中任一条就查 referer，不急着封。
