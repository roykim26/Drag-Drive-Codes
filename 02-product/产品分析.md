- 面向**全球英文搜索流量**，Google 为首要来源，首发仅英文单语；本期不做 hreflang、不做多语言。

## 一、站点定位

**一句话定位**：只用 30 秒就能拿到「现在还能用」的 Drag Drive Simulator 兑换码，并看清每个码的来源确认时间。

**定位拆解**：

| 维度 | 选择 | 理由 |
|---|---|---|
| 品类 | Roblox 单游戏 codes 垂直站 | 关键词与 SERP 全部指向单一游戏，铺多游戏会稀释首页相关性 |
| 竞争姿态 | 做「专门首页」，不做大站内页的复制品 | 调研显示 SERP 无首页，这是唯一结构空位 |
| 差异点 1 | 逐码级「最后确认时间 + 独立来源数」 | 竞品混入过期码、数值互相矛盾，透明度是最低成本的信任 |
| 差异点 2 | 移动端码表卡片化 + 一键复制 | Roblox 玩家移动端为主 |
| 差异点 3 | 把「下一码何时来」写成可回访信号 | 官方已过 20 万点赞门槛，新码随时可能发 |
| 明确不做 | 游戏攻略、车辆 tier list、私服码、Robux 代充 | 无关键词数据支撑，且代充有政策风险 |

**不做长期主力站**：定位是「低成本验证 + 可复用模板」，后续可横向复制到其他 Roblox codes 词（同一套构建脚本 + 数据结构）。

## 二、目标用户与任务

### Persona A：新玩家（占比最高）
- 场景：刚进游戏，缺 RP 买车，在手机上搜「drag drive simulator codes」。
- 任务：立刻拿到码 → 复制 → 回游戏兑换。
- 成功定义：从落地到复制第一个码 < 20 秒，不需要滚过任何长文。

### Persona B：回访玩家
- 场景：上周的码用完了，来找新码 / 确认旧码是否失效。
- 任务：看「更新时间」是否变了、有没有新码、旧码是否已归档。
- 成功定义：首屏就能看到 `Last checked: <date>` 与「New」标记。

### Persona C：怀疑型玩家
- 场景：在别的站输了码提示 invalid，来找「到底哪些是真的」。
- 任务：验证码的真伪、看兑换失败的排查步骤。
- 成功定义：能看到来源说明与失败原因清单，愿意收藏。

## 三、页面清单与信息架构

### 3.1 URL 结构（扁平、一层）

```
/                         首页：codes hub（主词）
/how-to-redeem/           兑换步骤 + 失败排查
/expired-codes/           过期码归档（按月/版本分组）
/rp-guide/                RP 是什么 + 怎么赚 + 码给的 RP 怎么花
/updates/                 版本更新与码的对应关系（V1.1.9 等）
/about/                   站点说明 + 核验方法（E-E-A-T 支撑）
/privacy/                 隐私政策（含 Cookie / 第三方广告说明）
/contact/                 联系方式（邮箱占位，需用户填真实邮箱）
/404.html                 404
/sitemap.xml  /robots.txt  /ads.txt（预留空文件，不填假内容）
```

> 说明：`/codes/` 不做独立页，直接由首页承接主词——避免首页与 codes 页自我竞争（keyword cannibalization）。

### 3.2 信息架构

```
首页 (Hub)
├─ 有效码表 ──────────► 兑换页（怎么用 / 失败怎么办）
├─ 过期码入口 ────────► 过期归档
├─ RP 说明入口 ───────► RP 指南
├─ 更新记录入口 ──────► 更新日志
└─ 核验方法入口 ──────► About
侧向互链：兑换页 ↔ 过期页 ↔ 更新页 ↔ RP 指南（每页 2–3 条正文内链）
页脚：About / Privacy / Contact / Sitemap
```

### 3.3 各页模块与目标词

| 页面 | title 目标词 | 核心模块（按顺序） | 广告位 |
|---|---|---|---|
| 首页 | drag drive simulator codes | 更新徽标条 → H1 + 结论句 → 有效码卡片列表（含复制） → 兑换 3 步 → 可能失效码 → 过期码摘要 → 新码何时来 → FAQ → 来源说明 | 码表下方 1 个 in-article + 文末 1 个 |
| /how-to-redeem/ | how to redeem codes in drag drive simulator | H1 → 分平台步骤（PC/移动） → 截图位（不用假图，占位说明） → 5 类失败原因 → 常见错误 → 回首页码表 | 步骤之后 1 个 |
| /expired-codes/ | drag drive simulator expired codes | H1 → 按月归档表 → 为什么失效 → 「还想要 RP 怎么办」 → 回首页 | 归档表下方 1 个 |
| /rp-guide/ | what is RP in drag drive simulator | H1 → RP 定义 → 获取途径 → 码给多少 RP（区间） → 花费方向 → 别买什么（Robux 与被骗提醒） | 正文中段 1 个 |
| /updates/ | drag drive simulator update codes | H1 → 版本时间线（V1.1.6–V1.1.9） → 每版对应码 → 下一版预期 | 时间线后 1 个 |
| /about/ | （品牌词） | 谁做的、怎么核验、不做什么 | 无（信任页不放广告） |
| /privacy/ /contact/ | （品牌词） | 标准文本 | 无 |

**页面数量决策**：首发 8 个 HTML（含 404）。理由：覆盖全部意图，且每页都有独立检索价值；再多会拖慢上线且分散权重。

## 四、内容策略与更新机制（核心难点）

codes 类内容的唯一护城河是**时效**。以下机制直接写进构建脚本与运营 SOP。

### 4.1 单一数据源

所有码存在一个数据文件（`04-site/data/codes.json`），字段：

```json
{
  "code": "DRAGDRIVESIMULATORSEPTEMBER26",
  "reward_min": 35000000,
  "reward_max": 35000000,
  "status": "active",            // active | unconfirmed | expired
  "added": "2026-09-27",
  "last_verified": "2026-11-15",
  "verified_by": ["official_game_page", "timesaver.gg", "rocodes.gg"],
  "note": "Named on the game page as the newest code"
}
```

页面里所有码表、sitemap 的 `lastmod`、首页的 `Last checked` 全部由此文件生成——**改一处，全站同步**，杜绝「首页说有 5 个码、过期页还有 3 个码没降级」这类事故。

### 4.2 核验分级（写进 About 页，作为信任资产）

| 级别 | 条件 | 页面标记 |
|---|---|---|
| **Confirmed** | ① 官方游戏页/官方 Discord 出现过 **且** ≥2 个独立追踪站列为有效；**或** ② 官方出现 **且** 游戏内实测通过（快速通道） | 绿色 `Confirmed` + 确认日期；实测过的另加蓝色 `In-game tested <date>` |
| **Reported** | 仅 1 个追踪站列为有效，官方未提及 | 黄色 `Reported` + 「进游戏试一下」 |
| **Expired** | ≥2 个来源列为过期，或官方已换新码 | 移入过期页，不显示在首页 |

**`In-game tested` 是附加标注，不是第四级**：只挂在已实测通过的 Confirmed 码上；站内目前没有任何系统性实测记录，因此线上所有码都不带这个徽标。实测通过的标准（真实账号兑换成功、RP 增加值与卡片一致、记录日期）见《码源获取与更新机制》§2.4。

**明示免责**：我们**不逐码**在游戏内实测，主要来源为官方页面 + 社区追踪站；只有争议码与读者举报码会进游戏实测并记录日期。Roblox 码可无预警失效。这段话出现在首页码表下方（callout），不是藏在页脚。

### 4.3 更新频率与触发条件

| 触发 | 动作 | 时限 |
|---|---|---|
| 每日 1 次（09:00 UTC） | 巡检官方页 / Discord 公告 / 群组 shout，抽查 1 个 active 码的社区投票或评论，失效则降级 | 每日 |
| 每月 1 日 | 检查月度码 `DRAGDRIVESIMULATOR<MONTH>26`，刷新 title 月份与 `Last checked` | 24h 内 |
| 官方版本更新（Roblox 页 Updated 变化） | 抓取新码，更新 `/updates/` 与首页 | 4h 内 |
| 点赞里程碑（官方写 `Next Code releasing at 200000 Likes`，当前 209K+） | 关注 Discord 公告，码出现即上 | 12h 内 |
| 订阅渠道（Discord 公告 / 群组 shout） | 新码确认后上首页，并标注来源与检查日期 | 2h 内（Reported）/ 24h 内（Confirmed） |
| 用户举报（码卡 mailto 入口或 contact） | 复核后降级并加 `expired` 标签 | 48h 内 |

### 4.4 时效性文案规则

- 首页 title 带月份（`Drag Drive Simulator Codes (November 2026)`），但**正文绝不写「本月码」这种会过期的表述**，一律写具体码名与日期。
- 每次刷新必须同步更新：`<title>` 月份、`Last checked` 显示、JSON-LD `dateModified`、sitemap `lastmod`。
- 过期码**不删除**，移入归档页——保持历史页面的收录与内链价值，也让回访用户看到「我们真的在维护」。

### 4.5 内容原创性要求（AdSense 合规）

- 不复制竞品文案；兑换步骤、失败原因、RP 说明均按实测官方流程重写。
- 每页必须有**竞品没有的信息**：逐码来源数、区间奖励口径、下一码触发条件、移动端复制说明。
- 不堆砌关键词：主词在 title / H1 / 首段 / 一处小标题出现即可，正文用 `codes`、`DDS codes`、`these codes` 自然替换。

## 五、变现承接

### 5.1 版位设计（本阶段只预留 DOM 容器，不插任何广告代码）

| 版位 | 位置 | 尺寸建议 | 逻辑 |
|---|---|---|---|
| A1 | 首页有效码表**之下**、兑换步骤之上 | responsive display | 用户已拿到价值，不打断核心任务 |
| A2 | 首页文末 FAQ 之后 | responsive display | 长停留用户的第二触点 |
| B1 | 每个功能页正文 1 处 | in-article | 保持 1 页 1 广告，避免密度过高 |
| — | 不放：首屏、码表内部、粘性底栏 | — | 会直接损伤复制体验与 Core Web Vitals |

实现方式：`<div class="ad-slot" data-slot="home-after-codes">` + 占位虚线框（仅开发时可见，上线前由开关隐藏）。

### 5.2 接入 AdSense 还需要什么（用户决策项）

1. 自有域名 + 已上线可访问（当前无域名）。
2. 站点通过审核：至少 15–20 篇有实质内容的页面更稳妥；**本首发仅 6 个内容页，可能偏少，需在第 2 个月扩页后再申请**（这点必须诚实告知）。
3. 必备页面：Privacy Policy（含 Cookie、第三方广告）、Contact、About。当前已包含。
4. `ads.txt`（审核通过后填入 pub-id，现在留空模板）。
5. Cookie 同意（EEA/UK 流量）：需接 CMP 或自建同意条，**未接入前不要开个性化广告**。
6. **受众合规重点**：Roblox 玩家以未成年人为主。AdSense 政策上不得将儿童导向内容用于个性化广告，且不得使用 `tag-for-child-directed-treatment`。站点应定位为「一般受众的游戏资讯」，不投放面向儿童的行为定向广告，并在隐私政策中说明。
7. 不得引导点击广告、不得把广告伪装成按钮（尤其「Copy」按钮附近）。

### 5.3 其他变现（后续可选，均不在本期）

- 联盟：Roblox 礼品卡/Robux 相关 CPS（需甄别合规渠道，注意避坑「免费 Robux」类违规 offer）。
- 站群内互链导流。

## 六、流量验证指标

### 6.1 指标与成功标准

| 阶段 | 时间 | 指标 | 达标线 |
|---|---|---|---|
| 技术验收 | 上线当天 | 收录就绪度 | sitemap 可访问、GSC 提交成功、0 控制台错误、移动端无横向溢出 |
| 收录 | 7 天 | 已收录页面数 | ≥ 5 / 8 |
| 起量 | 21 天 | GSC 自然点击 | ≥ 50 / 月（否则触发止损评估） |
| 排名 | 28 天 | 主词平均排名 | 进入前 50；任一长尾进前 30 |
| 质量 | 持续 | 平均互动时长 / 跳出率 | > 45s / < 75%（GA4 或 Cloudflare Analytics） |
| 回访 | 持续 | 回访用户占比 | > 15%（说明「新码预告」钩子有效） |

### 6.2 止损与加注

- **止损**：21 天点击 < 50 且主词 > 50 名 → 停止内容投入，保留站点，不再扩页。
- **加注**：28 天主词进前 20 或月点击 > 300 → 扩页（车辆 tier list、私服、任务攻略），并在第 2 个月申请 AdSense。

### 6.3 埋点

不引入重型分析。方案：Cloudflare Web Analytics（已接入，2026-11-15 起有数据，无 Cookie，免同意条）+ Google Search Console（网域资源已用 DNS TXT 验证并提交 sitemap）。GA4 仅在需要漏斗时再接。

## 七、风险清单

| 风险 | 影响 | 缓解 |
|---|---|---|
| 码快速失效 | 信任崩塌、跳出升高 | 逐码日期 + 每日巡检 + 一键降级流程 |
| 品牌名与域名未定 | 无法上线 | 单点常量，改一处全站生效 |
| 内容页数量不足，AdSense 审核被拒 | 变现延迟 | 第 2 个月扩至 15+ 页再申请 |
| 未成年受众广告政策 | 账号风险 | 不做个性化定向、不针对儿童、隐私政策写明 |
| 主词被大站长期压制 | 流量不达预期 | KPI 绑长尾与收录，不绑主词前三 |
| 官方改码规则/停更 | 站点价值归零 | 保留模板，可平移到其他 codes 词 |
